# ESP32 AirPlay & Bluetooth 歌词音箱设计方案

- **日期**：2026-10-22
- **状态**：已审批通过 (Approved)
- **项目规模**：完整项目 (Project)

---

## 1. 概述与设计意图 (Intent & Why)

构建一款基于 **ESP32 (WROVER-E)** 的桌面智能音箱。该音箱同时支持苹果 **AirPlay (RAOP)** 投屏和通用 **经典蓝牙（Bluetooth A2DP Sink）** 音频播放（完美支持 Apple Music 与 YouTube Music），并外接一块 2.8 ~ 3.5 寸彩色 TFT 液晶屏，实时获取并平滑滚动高亮展示当前正在播放歌曲的同步歌词。

---

## 2. 目标与非目标 (Goals, Non-Goals, Anti-Goals)

### 2.1 目标 (Goals)
1. **双无线音频输入（单芯片原生支持）**：
   - 局域网内支持苹果设备通过 AirPlay 1 (RAOP) 协议投送 44.1kHz 16-bit ALAC 无损/CD 级音频。
   - 手机/电脑直接通过经典蓝牙 A2DP Sink 协议连接播放音频，支持 AVRCP 歌曲信息同步与播控。
2. **高质量数字音频输出**：
   - ESP32 通过 I2S 数字接口直连 MAX98357A D 类功放模块，直接驱动 4Ω 3W~5W 扬声器。
3. **实时歌词同步显示**：
   - 提取音频流中的歌曲元数据（曲名 Title、歌手 Artist）。
   - 通过 Wi-Fi 自动调用公共歌词 API（如 LRCLIB、网易云等开放接口）检索并下载对应 `.lrc` 文件。
   - 解析时间戳，根据播放进度在屏幕上逐行平滑滚动，当前句高亮放大显示。
4. **沉浸式 UI 交互**：
   - 采用方案 A 布局：顶部连接状态与曲目栏，中间 5 行平滑滚动歌词，底部时间与进度条。

### 2.2 非目标 (Non-Goals)
1. **本地音乐播放器**：首期不要求读取 MicroSD 卡进行本地音乐文件解码（专注无线投播）。
2. **麦克风语音助手**：不集成语音唤醒或智能音箱唤醒词交互，避免占用芯片算力与麦克风通道。
3. **内置电池超长续航**：设备定位桌面摆件，采用 5V Type-C 持续供电，不设计复杂的锂电充放电管理。

### 2.3 反目标 (Anti-Goals)
- **避免严重的音频卡顿与爆音**：网络传输、歌词 HTTP 拉取及 UI 渲染绝不能阻塞 I2S DMA 音频推流。
- **避免不可读的杂乱排线与严重杂音**：模块布局与地线设计必须分离音频模拟地与数字地/电源回路。

## 3. 硬件搭建路线比选与权衡 (Approaches Considered)

在方案构思阶段，评估了两种硬件实现路线：

| 方案 | 硬件形态 | 优势 | 劣势与权衡 | 最终决策 |
| :--- | :--- | :--- | :--- | :--- |
| **方案 1：一体化音频开发板** | 采用 ESP32-S3-Korvo 或 ESP32-S3-BOX 开发套件 | 板载 Codec、功放与屏幕接口，零接线，音质纯净，开箱即用 | 硬件外形固定，元器件不可自由搭配，成本偏高 (120~200元) | 未采纳 |
| **方案 2：分立模块自由组装** (用户选定) | ESP32-WROVER-E + MAX98357A 功放 + SPI 彩屏 + 扬声器 | 自由度极高，单芯片原生支持经典蓝牙与Wi-Fi，零部件成本低 (约 60~80元)，免焊接即插即用 | 需要手动通过杜邦线接线，需严格按照避开内部 PSRAM 的引脚方案连线 | **选定采用** |

## 4. 详细硬件物料清单与接线规划 (BOM & Pinout)

### 4.1 核心硬件物料清单 (BOM)
1. **主控板（已选定确认）**：**ESP32-WROVER-E (CH340) 开发板**（带 8MB PSRAM，内置 PCB 天线，已焊接排针）
   - 规格：16MB Flash + **8MB PSRAM**、内置 PCB 天线、**已出厂焊接排针**（直接插面包板或杜邦线，免电烙铁）。
   - 核心优势：原生搭载 Wi-Fi 与经典蓝牙双模（BR/EDR + BLE），单芯片搞定 AirPlay + 蓝牙音箱。
2. **数字功放模块**：**MAX98357A I2S D类功放板**
   - 3W 单声道输出（高效低发热，直接 I2S 数字输入，无需外挂额外 DAC）。
3. **扬声器单元**：**4Ω 3W ~ 5W 全频微型喇叭**（建议带小音腔/共振腔，提升低音表现）。
4. **显示屏**：**2.8 寸或 3.2 寸 TFT 液晶屏模块**
   - 驱动芯片：ST7789 或 ILI9341，分辨率 320×240，标准 SPI 通信接口。
5. **线材与配件**：
   - 面包板 1 块（830 孔或 400 孔）。
   - 杜邦线（公对母、公对公若干）。
   - Type-C 数据线（5V 2A 手机充电头供电）。

### 4.2 GPIO 引脚分配规划 (Pinout Allocation for WROVER-E)

> [!IMPORTANT]
> **关键引脚避坑**：ESP32-WROVER 模组内部将 `GPIO 16` 和 `GPIO 17` 用于连接外扩 PSRAM，**严禁外部接线占用 GPIO 16/17**。以下规划已全部避开 PSRAM 内部总线与下载引脚。

#### 4.2.1 I2S 音频连接 (MAX98357A)
| MAX98357A 引脚 | ESP32-WROVER 引脚 | 功能描述 |
| :--- | :--- | :--- |
| **VIN** | 5V / VBUS | 功放电源输入（连接 5V 保证音量充足） |
| **GND** | GND | 电源地线 |
| **BCLK** | GPIO 25 | 位时钟 (Bit Clock) |
| **LRC (LRCLK)** | GPIO 26 | 声道选择时钟 (Word Select) |
| **DIN** | GPIO 27 | I2S 串行音频数据 |
| **SD_MODE** | 悬空 / 上拉 | 默认左右声道混音为单声道 |
| **GAIN** | 悬空 (默认 9dB) | 增益配置 |

#### 4.2.2 屏幕 SPI 连接 (ST7789 / ILI9341 320x240)
| 屏幕引脚 | ESP32-WROVER 引脚 | 功能描述 |
| :--- | :--- | :--- |
| **VCC** | 3.3V | 屏幕逻辑供电 |
| **GND** | GND | 电源地线 |
| **CS** | GPIO 5 | SPI 片选信号 (VSPI CS) |
| **DC / RS** | GPIO 2 | 命令 / 数据选择 |
| **RST** | GPIO 4 | 硬件复位引脚 |
| **SCL / SCK** | GPIO 18 | SPI 时钟 (VSPI SCLK) |
| **SDA / MOSI**| GPIO 23 | SPI 主机输出 (VSPI MOSI) |
| **BLK** | GPIO 21 (PWM) | 背光控制（支持屏幕亮度调节） |

## 5. 软件系统架构 (Software Architecture)

### 5.1 整体分层架构

```
+--------------------------------------------------------------+
|                     用户界面层 (LVGL 8.x/9.x)                 |
|   [顶部状态栏]        [中间5行滚动歌词组件]        [底部进度条]  |
+--------------------------------------------------------------+
                               |
+--------------------------------------------------------------+
|                     歌词引擎与调度系统                        |
|   - LRCLIB / NetEase 开放 HTTP API 客户端                     |
|   - .lrc 时间戳解析器 (毫秒级队列索引)                        |
|   - 播放进度估算与平滑补间定时器                              |
+--------------------------------------------------------------+
                               |
+--------------------------------------------------------------+
|                     多源音频输入处理系统                      |
|   - 协议 A: Apple AirPlay 1 (RAOP RTSP/RTP/ALAC 接收器)       |
|   - 协议 B: Bluetooth A2DP Sink + AVRCP 控制器 (曲目元数据提取)   |
|   - 音频源仲裁与自动切换状态机                               |
+--------------------------------------------------------------+
                               |
+--------------------------------------------------------------+
|                     音频输出管道 (I2S DMA)                    |
|   - RingBuffer 环形缓冲 + MAX98357A I2S 驱动 (GPIO 25,26,27)  |
+--------------------------------------------------------------+
```

### 5.2 核心流程与数据流

1. **音频接收与播放**：
   - 当检测到 AirPlay 连接请求或手机蓝牙配对连接时，音频通道初始化，解码后的 PCM 数据写入 I2S DMA 环形缓冲区，推送至 MAX98357A 播放。
   - 蓝牙与 AirPlay 互斥：AirPlay 唤醒时自动暂停蓝牙通道；空闲时释放。
2. **元数据提取与歌词触发**：
   - **Bluetooth**：从 AVRCP `ESP_AVRC_RN_TRACK_CHANGE` 事件中捕获 `Title` 与 `Artist`。
   - **AirPlay**：从 DACP / DAAP 元数据包中解析 `minm`（歌名）与 `asar`（歌手）。
   - 当曲目改变时，触发异步歌词检索任务。
3. **歌词获取与解析 (Lyrics Service)**：
   - 优先通过 Wi-Fi 调用 **LRCLIB API**：`GET https://lrclib.net/api/get?artist_name={artist}&track_name={track}`。
   - 返回标准 JSON，内含 `syncedLyrics`（标准 `[mm:ss.xx]` 格式文本）。
   - ESP32-WROVER 解析文本构建歌词时间戳列表 `[{time_ms, text}]` 存放于 PSRAM 中。
4. **界面动态渲染 (方案 A 布局)**：
   - 定时器以 100ms 刷新率计算当前曲目播放位置，二分查找定位当前歌词索引。
   - 驱动 LVGL 列表控件自动滚动：上一句、当前高亮放大句（重点青蓝色彩渲染）、下一句过渡。

## 6. 预留给构建者的工程细节 (Left to the Builder)

1. **固件技术栈选择**：
   - 推荐方案：PlatformIO + Arduino / ESP-IDF 混合架构，基于成熟的 `ESP32-A2DP` 库处理蓝牙接收，搭配 lightweight RAOP receiver 处理 AirPlay，以及 `TFT_eSPI` / `lvgl` 渲染界面。
2. **断网与未匹配歌词的处理**：
   - 当无可用 Wi-Fi 或歌曲未在公共库搜到歌词时，屏幕自动平滑回退到显示“大字号歌名 + 歌手 + 动态音频伪频谱”的优雅备用界面。
3. **结构与声学音腔**：
   - 喇叭建议固定在密闭小箱体（3D 打印或木质小盒）中，与电路板隔离，避免箱体漏气与机震破音。

## 7. 验证计划 (Verification Plan)

1. **硬件基础验证**：
   - 单独测试 MAX98357A 播放正弦波 / 试音音频，确认无明显失真与底噪。
   - 单独测试 TFT 屏幕 SPI 通信，点亮背光并跑通 LVGL 示例。
2. **音频连接验证**：
   - 手机连接蓝牙，播放 YouTube Music，验证音频流畅无破音，AVRCP 能正确打印歌名。
   - iPhone 连接 AirPlay，播放 Apple Music，验证投屏与音质。
3. **歌词与界面闭环测试**：
   - 连上 Wi-Fi 后播放主流中英文歌曲，验证歌词接口能否 1~2 秒内命中并对齐滚动。
